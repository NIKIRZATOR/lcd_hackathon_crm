# Справочник конструктора плейбуков

Конструктор собирает **шаблон** захода для KAM, не живой заход. Открывается из **Управление → Создать плейбук** или **Открыть в конструкторе**.

Доступ: руководитель и администратор.

## С нуля или на основе шаблона

- **С нуля** — пустой путь, фазы и этапы добавляете сами.
- **На основе существующего** — копия выбранного плейбука в статусе draft. Исходник не меняется. Выберите шаблон и нажмите **Открыть**.

Черновик без названия в список плейбуков не попадает, пока не зададите имя.

## Шапка

- Название и описание плейбука.
- **Настройка / Предпросмотр** — одно и то же содержимое, предпросмотр без ручек редактора.
- **Сохранить черновик** / **Опубликовать**. Опубликованный шаблон нельзя править напрямую: нужна **новая версия** (отдельный draft).
- **Доступ:** всем KAM или выбранным (поиск по списку).

## Путь слева

Фазы (группы) и этапы внутри. Перетаскивание меняет порядок и фазу. Номер считается сверху вниз.

- **Добавить фазу / этап**. Первый этап без фаз создаёт фазу «Основной путь».
- Меню фазы: переименовать, удалить (этапы уходят в соседнюю фазу).
- Меню этапа: переименовать, дублировать, удалить.
- Жёлтый/красный ⚠ — предупреждение или ошибка конфигурации (наведите, чтобы прочитать).

## Этап справа

Название, фаза, SLA в днях, «можно пропустить», описание, затем блоки.

**Контроль исполнения** — постоянный монитор: без SLA, без пропуска, в предпросмотре без кнопки закрытия.

## Блоки

Порядок блоков = порядок на экране KAM. Меню ⋯ → удалить блок.

### Информационные поля
Набор готовых фактов (дата встречи, номер договора и т.д.). Обязательность ставится у каждого поля. Технические ключи вводить не нужно.

### Чеклист
Пункты закрытия этапа.
- **Ручной** — отмечает менеджер.
- **Автоматический** — привяжите **факт**; на живом заходе пункт закроется, когда факт заполнен. В конструкторе это только настройка.

### Комментарий
Текстовое поле. Можно сделать обязательным и задать минимальную длину.

### Ручное подтверждение
Галочка «подтверждаю». Обычно обязательная.

### Один документ
Слот одного файла: тип (договор, лицензия, акт…), обязательность, форматы, необязательный шаблон (выбирается файл, пока сохраняется имя).

### Несколько документов
Несколько слотов, у каждого свой тип и обязательность.

### Контакт вуза
Требования: человек, телефон/почта, роль.

### Договор
Номер, дата, файл подписанного договора.

### Лицензия
Номер, срок, файл.

### Доступ к продукту
Статус передачи, строка доступа, акт. Это не блок лицензии.

### Преподаватель
Человек, продукт, дата обучения, статус, сертификат.

### Учебный план
Файл плана и/или комментарий согласования.

### LMS-показатели
Карточка метрик захода: студенты, заявки, последний сигнал. В предпросмотре данных нет, на заходе приходят из интеграций.

### Сигналы сайта
Последний сигнал сайта площадки. В предпросмотре пусто.

## Предпросмотр

Показывает этап как у KAM: описание, SLA, блоки, кнопка **Закрыть этап** (неактивна). Данные не теряются при возврате в настройку.

## Публикация

Проверка: имя плейбука, есть этапы, у этапов имена и непустые блоки, у документов — типы. После публикации правка только через новую версию. Уже идущие заходы не меняются.

## Что KAM увидит

Опубликованный плейбук доступен при создании захода тем KAM, кому выдан доступ. Конструктор не подставляет живые студенты и контакты — только каркас этапа.
