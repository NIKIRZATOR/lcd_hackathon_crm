# Организации

Раздел **«Организации»** — это единый справочник учебных заведений, с которыми работает ИТ-школа Ростелекома.
(скрин 1)
Здесь можно:

- найти нужную площадку;
- посмотреть состояние сотрудничества;
- увидеть закреплённого KAM;
- работать с контактами;
- видеть активные программы и их текущие этапы;
- контролировать договоры и лицензии;
- работать с преподавателями;
- просматривать документы и историю событий;
- запускать новые программы.

Раздел используется не только для вузов. Организацией может быть, например:

- университет;
- институт;
- колледж;
- школа;
- другая образовательная площадка.

---

# Основные понятия

## Организация

**Организация** — учебное заведение или отдельная образовательная площадка, с которой ведётся работа.

Организация хранит общие сведения:

- название;
- тип;
- регион;
- город;
- ответственного KAM;
- контакты;
- договоры;
- преподавателей;
- документы;
- историю взаимодействия.

Статус конкретного внедрения продукта хранится не на самой организации, а внутри её программ.

---

# Программа

**Программа** — конкретное взаимодействие по связке:

**организация × ИТ-направление × продукт**.

Например:

**НИТУ МИСИС × Анализ данных × Специалист по анализу данных**

У одной организации может быть несколько программ одновременно.

Например:

```text
Организация
НИТУ МИСИС

├─ Анализ данных × продукт A
├─ DevOps × продукт B
└─ Информационная безопасность × продукт C
```

Каждая программа развивается независимо:

- имеет свой плейбук;
- находится на своём этапе;
- имеет отдельные сроки;
- лицензию;
- преподавателя;
- учебное окно;
- показатели студентов и заявок;
- состояние здоровья.

---

# Плейбук и взаимодействие
(скрин 5)
Для каждой программы запускается процесс по выбранному **плейбуку**.

Плейбук определяет маршрут программы.

Например:

- полный цикл;
- расширение;
- продление лицензии;
- короткий школьный цикл;
- замена преподавателя.

Текущий этап программы показывает, где сейчас находится работа.

Подробная работа с этапами описана в разделе **Workflow**.

---

# Список организаций
(скрин 2)
При открытии раздела отображается список доступных пользователю организаций.

В зависимости от роли это могут быть:

- организации самого KAM;
- организации команды;
- все организации системы.

---

# Сводка

В верхней части страницы отображается краткая сводка по текущему списку.

Например:

- количество организаций;
- количество программ;
- количество жёлтых и красных организаций;
- количество организаций без активных программ.

Сводка помогает быстро понять состояние портфеля.

---

# Поиск

Поиск позволяет найти организацию по:

- названию;
- городу.

---

# Фильтры
(скрин 6)
Можно отобрать организации по:

- региону;
- типу;
- направлению;
- продукту;
- периоду активности;
- KAM — если роль пользователя позволяет видеть команду.

Кнопка **«Сбросить»** очищает фильтры.

---

# Таблица организаций

Для каждой организации отображаются ключевые признаки.

Обычно:

- название;
- город;
- тип;
- количество программ;
- здоровье;
- ближайший риск.

Для руководителя и администратора также может отображаться закреплённый KAM.

Нажатие на строку открывает карточку организации.

---

# Здоровье организации
(скрин 3)
Health организации используется как быстрый индикатор состояния её активных программ.

Он помогает понять:

- всё ли в порядке;
- есть ли программы, требующие внимания;
- есть ли критические проблемы.

Важно:

**здоровье организации не является отдельным ручным статусом.**

Оно формируется из состояния её программ.

Поэтому одна организация может иметь несколько программ с разным состоянием.

Например:

```text
МИСИС

DevOps              green
Data Science        yellow
Cybersecurity       red
```

В списке организация должна помогать быстро заметить худший или наиболее важный риск.

---

# Карточка организации
(скрин 9)
Карточка организации собирает всю информацию по площадке в одном месте.

В верхней части отображаются:

- название;
- тип организации;
- регион;
- город;
- ответственный KAM;
- здоровье;
- основные действия.

---

# Основные действия

В зависимости от роли доступны:

### + Программа

Создать новую программу для этой организации.

### Синхронизировать

Обновить данные, которые поступают из связанных источников.

### Отчёт по организации

Сформировать или открыть сводную информацию по площадке.

### Сменить KAM
(скрин 7)
Доступно руководителю и администратору при соответствующих правах.

---

# Вкладка «Программы»
(скрин 10)
Это основной рабочий раздел карточки.

Здесь отображаются все программы организации.

Для каждой программы можно видеть:

- направление;
- продукт;
- плейбук;
- текущий этап;
- здоровье;
- учебное окно;
- студентов;
- заявки;
- лицензию;
- ответственного.

Нажатие на строку программы открывает её Workflow.

---

# Зачем нужна вкладка «Программы»

Она отвечает на вопрос:

**«Что именно сейчас происходит с этой организацией?»**

Например организация может одновременно:

- проходить первый полный цикл по одному продукту;
- продлевать лицензию по второму;
- менять преподавателя по третьему.

Все эти процессы видны отдельно.

---

# Создание программы
(скрин 11 и 12)
Чтобы запустить новую программу:

1. Откройте карточку организации.
2. Нажмите **«+ Программа»**.
3. Выберите направление.
4. Выберите продукт.
5. Укажите учебное окно.
6. Выберите предложенный плейбук или другой допустимый.
7. Подтвердите создание.

После этого откроется Workflow созданной программы.

---

# Как выбирается плейбук

Система может предложить наиболее подходящий плейбук в зависимости от ситуации.

Например:

### Полный цикл

Для нового полноценного сотрудничества.

### Расширение

Если организация уже работает с Ростелекомом, но подключается новый продукт или направление.

### Продление лицензии

Если требуется продлить уже действующую лицензию.

### Короткий школьный цикл

Для сценариев, где полный вузовский процесс избыточен.

### Замена преподавателя

Если необходимо заменить действующего носителя продукта.

Пользователь видит предложенный маршрут до создания программы.

---

# Защита от дублей
(скрин 13)
На одну и ту же активную связку:

**организация × направление × продукт**

не должна создаваться вторая параллельная программа без необходимости.

Если такая программа уже существует, система должна предложить открыть текущую.

Это защищает данные от дублирования.

---

# Вкладка «Люди»
(скрин 14)
Здесь хранятся контакты организации.

Контакт может быть:

- основным;
- привязанным ко всей организации;
- связанным с конкретной программой.

---

# Что хранится у человека

Например:

- ФИО;
- роль;
- должность;
- телефон;
- email;
- связанная программа;
- признак основного контакта.

---

# Добавление человека

Нажмите **«Добавить человека»**.

Заполните доступные данные.

Контакт можно связать:

- со всей организацией;
- с конкретной программой.

---

# Основной контакт

Основной контакт — человек, через которого преимущественно ведётся работа с площадкой.

Он используется в Workflow, например на этапе **«Поиск контакта»**.

Если основной контакт изменился, его можно переназначить.

---

# Скрытие контакта

Если человек больше не участвует во взаимодействии, его не обязательно удалять из истории.

Используется действие **«Скрыть»**.

Это позволяет сохранить историю, но не показывать неактуального человека среди активных контактов.

При необходимости скрытых людей можно снова показать.

---

# Вкладка «Договоры и лицензии»

Здесь собраны юридические и лицензионные данные организации.

---

# Рамочные договоры

Договор может содержать:

- номер;
- дату;
- срок;
- файл;
- признак действующего договора.

Рамочный договор относится к организации в целом и может использоваться в нескольких программах.

---

# Лицензии

Лицензия относится уже к конкретной программе или продукту.

Можно видеть:

- продукт;
- номер лицензии;
- дату подписания;
- срок действия;
- статус передачи;
- файл;
- сведения о доступе.

---

# Почему лицензия важна

Срок лицензии используется не только для хранения документа.

Система может использовать его для:

- контроля срока;
- подсветки рисков;
- health score;
- сценария продления;
- контрольного этапа Workflow.

Поэтому актуальность даты окончания лицензии критична.

---

# Вкладка «Преподаватели»

Здесь отображаются преподаватели, связанные с организацией и её продуктами.

Для преподавателя могут отображаться:

- ФИО;
- продукт;
- дата обучения;
- срок квалификации;
- статус;
- активность LMS.

---

# Возможные статусы

Например:

- к обучению;
- обучен;
- ведёт;
- ушёл.

Статус используется в Workflow.

Например:

- на этапе обучения преподавателя;
- при подтверждении готовности;
- при ведении занятий;
- при запуске сценария замены.

---

# Квалификация преподавателя

Дата квалификации помогает контролировать, может ли преподаватель продолжать вести продукт.

Если срок закончился, система может подсветить проблему в Workflow или Контроле исполнения.

---

# Вкладка «Документы»

Здесь находится единый список файлов организации.

Для файла могут отображаться:

- название;
- тип;
- программа;
- этап;
- автор загрузки;
- дата загрузки.

---

# Зачем нужен общий список документов

Документы физически появляются на разных этапах Workflow:

- протокол встречи;
- договор;
- лицензия;
- сертификат;
- учебный план;
- отчёт.

Во вкладке организации их можно просматривать из одного места, не открывая каждый этап отдельно.

---

# Важно про документы Workflow

Если этап требует файл в конкретном слоте, файл должен быть загружен именно туда.

Простое наличие файла во вкладке **«Документы»** не обязательно означает, что условие этапа выполнено.

---

# Вкладка «Лента»

Лента показывает историю событий организации.

Например:

- создана программа;
- добавлен контакт;
- изменён KAM;
- загружен документ;
- изменена лицензия;
- завершён этап;
- создано продление.

---

# Что показывает событие

Обычно:

- дату;
- время;
- тип события;
- описание;
- пользователя.

Лента помогает восстановить историю работы с площадкой.

---

# KAM

KAM видит организации, закреплённые за ним.

Основные задачи:

- открыть нужную площадку;
- работать с контактами;
- создавать программы;
- контролировать текущий статус взаимодействия;
- открывать Workflow;
- работать с договорами, лицензиями и преподавателями.

---

# Руководитель

Руководитель работает с организациями команды.

Дополнительно доступны:

- фильтр по KAM;
- отображение KAM в списке;
- назначение ответственного;
- смена ответственного.

---

# Смена KAM
(скрин 7)
Действие **«Сменить KAM»** позволяет передать организацию другому сотруднику команды.

После назначения нового KAM связанные активные программы должны отображаться в его рабочем портфеле.

При этом история предыдущего ответственного сохраняется в системе.

---

# Администратор

Администратор работает со всем справочником организаций.

Дополнительно доступны функции, связанные с качеством данных и импортом.

---

# Импорт организаций
(скрин 8)
Для массового добавления или обновления каталога используется **«Загрузить каталог»**.

Типовой процесс:

1. Скачать шаблон — если требуется.
2. Выбрать файл.
3. Сопоставить колонки файла с полями CRM.
4. Проверить предпросмотр.
5. Исправить найденные ошибки.
6. Подтвердить импорт.

---

# Что важно при импорте

Импорт не должен слепо перезаписывать существующие организации.

Перед применением система должна позволять понять:

- какие строки будут созданы;
- какие обновлены;
- какие содержат ошибки;
- какие данные не удалось сопоставить.

---

# Организации без KAM

Администратор или руководитель может отдельно найти организации, которым ещё не назначен ответственный.

Такие организации требуют назначения KAM до полноценной работы.

---

# Если у организации нет программ

Это не ошибка.

Организация может уже быть добавлена в портфель, но процесс внедрения ещё не запущен.

В таком случае следующий типовой шаг:

**создать первую программу**.

---

# Если программа уже существует

Не создавайте дубликат.

Откройте существующую программу и продолжайте работу в её Workflow.

---

# Если контакт больше не работает

Не удаляйте историю без необходимости.

Скройте неактуальный контакт и назначьте нового основного.

---

# Если лицензия изменилась

Обновите сведения в карточке лицензии.

Изменение срока или статуса может повлиять на:

- здоровье программы;
- Workflow;
- Контроль исполнения;
- сценарий продления.

---

# Если преподаватель ушёл

Измените его статус.

Дальнейшие действия выполняются через соответствующий Workflow или плейбук замены преподавателя.

---

# Как связаны «Организации» и «Workflow»

Разделы решают разные задачи.

## Организации

Отвечает на вопрос:

**«С кем мы работаем и что у этой площадки есть?»**

Здесь:

- люди;
- договоры;
- лицензии;
- преподаватели;
- документы;
- список программ.

## Workflow

Отвечает на вопрос:

**«На каком шаге сейчас находится конкретная программа и что нужно сделать дальше?»**

---

# Пример

Организация:

**НИУ ИТМО**

В карточке:

```text
Люди
├─ основной контакт
└─ преподаватель

Договор
└─ действующая рамка

Программы
├─ DevOps × продукт A
│  └─ этап: Подписание лицензии
│
└─ Data Science × продукт B
   └─ этап: Ведение занятий
```

То есть карточка организации — это **единая точка входа во всё сотрудничество**, а Workflow управляет каждой отдельной программой.

---

# Главное правило раздела

Не пытайтесь хранить статус сотрудничества одной отметкой на уровне организации.

У одной площадки может быть несколько программ в разном состоянии.

Поэтому:

**организация — это контекст сотрудничества; программа — конкретное внедрение; Workflow — процесс этого внедрения.**
